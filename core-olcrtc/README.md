# Патч ядра olcrtc: рабочий datachannel через WbStream

**Состояние: доведён и проверен на стенде.** Отладка убрана, апстримные таймауты не тронуты,
регресс vp8channel проверен. В бой не катилось: нужен пересобранный `.aar` для приложения.

База: `openlibrecommunity/olcrtc`, коммит `513be68` (04.08.2026).
Патч: `apply.py` — текстовые замены в двух файлах, идемпотентен.
Запуск: `python3 apply.py <клон olcrtc>`. Формат diff не используется намеренно:
один потерянный пробел в контекстной строке роняет сборку с «corrupt patch»,
на этом уже потеряли один прогон CI.

## Что чинит

Апстримный `datachannel` через носитель WbStream не собирает пару вообще: сервер логирует
`session opened`, клиент падает по таймауту либо на `CONTROL_PING`. На vp8channel та же пара
собирается за секунду.

**Корень (замерено, не гипотеза):** участник LiveKit начинает получать data-пакеты не сразу
после входа в комнату. Сервер отвечает мгновенно, и `SERVER_WELCOME` улетает в пустоту.
Хронология: приветствие 137 байт в 13:52:59 клиент не получил, пакеты 52 и 128 байт
в 13:53:09 и 13:53:19 получил все до единого.

## Что в патче

| Правка | Файл | Зачем |
|---|---|---|
| Ждём первый пакет от пира перед `CLIENT_HELLO` | `internal/client/client.go` | **главная.** Первый входящий пакет = доказательство, что наша подписка активна и ответ будет кому принять. Сервер шлёт keepalive раз в 10 с, он и разблокирует. Потолок ожидания 20 с, превышение не фатально (идём дальше, решает обычный дедлайн) |
| `RequireTargetedPeer` только для транспортов с эпохами | `internal/client/client.go` | у datachannel нет эпох, у движка livekit нет адресной отправки (`SendTo` отсутствует), поэтому ответ всегда широковещательный, а клиент такие молча выбрасывал |
| Пропуск залётных `CONTROL_*` фреймов | `internal/handshake/handshake.go` | у серверной стороны эта защита уже есть (`server.acceptHandshake`, `maxStaleRetries`), у клиентской не было |

Прогрев включается **только** для транспортов без эпох (`isBroadcastOnlyTransport`), поэтому
vp8channel идёт как в апстриме, без лишних задержек. `DefaultTimeout` оставлен апстримный (15 с).

## Замеры (стенд: нога LXC 211 + клиент LXC 204, файл с нашего VPS)

| | vp8channel | datachannel с патчем |
|---|---|---|
| 10 МБ ×5 | 8.14-8.31 Мбит/с | **15.4-19.7 Мбит/с** |
| 20 МБ | 8.82-9.01 Мбит/с | **19.1-30.1 Мбит/с** |
| 8 передач подряд без пауз | сыпался (2 обрыва + 4 ошибки TLS из 13) | **8 из 8, ноль обрывов** |
| Задержка | 325-430 мс | 343-376 мс |
| Холостой расход с живым пиром | ~415 МБ/сут | ~53 МБ/сут |
| Подъём туннеля | 1-3 с | **5 с** (спокойная комната) |

Проверка повторяемости: 5 перезапусков подряд — поднялся 5 из 5. Время скачет (10-45 с),
когда перед этим клиент падал: его падение заставляет ногу переустановить сессию, и следующая
попытка попадает в это окно. В спокойном состоянии (сценарий телефона) — **5 секунд, ноль падений**.

**Регресс vp8channel на патченом ядре:** подъём 3 с, падений 0, прогрев не применяется.
Скорость там 6.6-8.4 Мбит/с — это просадка самого апстрима `513be68` (воспроизводится и без
патча), а не следствие правок.

## Чего НЕ сделано

1. **Не собран `.aar` с патчем.** Приложение тянет чистый апстрим по `OLCRTC_REF`
   (`build-olcrtc.yml`, `release.yml`) — workflow надо научить накладывать этот файл.
   Пока телефон на старом ядре, datachannel для него не поднимется.
2. **Не проверено на живом телефоне.**
3. **Нужен второй аккаунт WB на постоянку**: datachannel работает только между двумя
   аккаунтами, гость данные слать не умеет. Токен снят 06.08, лежит на ноге
   (`/opt/olcrtc/wb_token_dom.txt`, 600).
4. **Не отправлено в апстрим.** Правки общего характера, апстриму они бы пригодились.

## Как собрать

Go на узлах нет, собиралось в контейнере на LXC 204 (там docker), дерево — `/opt/olcbuild/src`:

```bash
git clone --depth 1 https://github.com/openlibrecommunity/olcrtc.git src
python3 /path/to/core-olcrtc/apply.py src
docker run --rm -v /opt/olcbuild:/out -w /out/src golang:1.26.3 bash -c \
  'CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o /out/olcrtc.final ./cmd/olcrtc'
```

Для `.aar`: gomobile с `-checklinkname=0` (см. `magefile.go`, цель `Mobile`).
